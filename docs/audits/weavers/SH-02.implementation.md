## Design and ownership

Core 0.21.5 adds a small optional HTTPClientLifecycle mixin and configuration
rejection helper; source adapters retain request construction, lazy-client defaults,
source semantics and existing pacing. HTTP ownership is explicit: absent client
means lazy ownership; injected client means borrowing. Clients require an absolute
HTTP(S) base URL and cannot be injected after closure. The injected client's actual
base URL governs its relative requests and fingerprint; base_url configures owned
clients only. Unknown-option errors list keys, never values.

BaseWeaver provides async context management and an optional aclose hook. Shared
and NCBI dispatch close distinct adapters, attempting other adapters on normal
cleanup failures and reporting an ExceptionGroup. Cancellation propagates. Owned
clients close once; borrowed clients remain usable by their owner. Closed HTTP
backends are terminal and must be reconstructed. Finish active work before closing.
Resource-free local backends retain their existing per-call connection ownership.

GTDB/Wikipedia use bounded workers (four by default), per-batch distinct-input
fetches and a five-requests/second default through the existing pacing seam.
Operational concurrency is excluded from semantic identity. Existing proper
PDBe/QuickGO/Reactome/STRING remote descriptors are retained, rather than nested
under another hashing layer. Newly missing endpoint identity is hashed with source
semantics. This identifies configuration, not frozen remote content.

New scaffolds reject unknown builder options and depend on core >=0.21.5, preventing
recurrence. Source-specific settings remain explicit and are documented in
[construction and lifetime](../../weaver-configuration.md).

## Compatibility and migration

- Previously discarded builder keywords now raise BackendConfigurationError.
  Remove misspellings/unsupported options and use the documented public signatures.
  Supported configuration can be passed through WeaverFactory.build(id, config).
- NCBI api_key alone now selects/configures API. With an injected client, api_key
  must match its api-key header, or be omitted; borrowed client headers are not mutated.
- AGORA configured construction no longer enables downloads implicitly. Pass
  auto_setup=True explicitly when that acquisition is intended.
- GTDB tree/release/refresh settings now take effect; its configured wrapper rejects
  calls that select no source. Empty discovery construction remains valid.
- HTTP users should use async with weaver or await weaver.aclose() after batches.
  Injected clients remain caller-owned. Existing remote fingerprint keys may change
  where source identity was previously incomplete; no database schema changes occur.
- Core 0.21.5, weaverkit 0.6.7 and all 17 affected weavers are patch-bumped; their
  spec/project/vocab versions agree, dependent core floors and uv.lock are updated.
  Generated catalogs are refreshed; NCBI's custom vocab is preserved.
