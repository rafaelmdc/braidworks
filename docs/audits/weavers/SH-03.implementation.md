## Design and semantics

Validation is a source-local adapter boundary: pure helpers validate the source
shape and correlation before projection. Existing backend orchestration catches only
HTTP errors, JSON/Unicode decoding failures and explicit private source-validation
exceptions. Cancellation, RuntimeError and unrelated ValueError faults propagate.
No biological assumptions or source schemas were added to core. No universal
validation hierarchy or blanket catch-all failure wrapper was introduced.

Request chunks are the failure unit for an untrustworthy bulk payload; the backend
preserves successes from independent requests and still attempts later chunks.
Results retain input order, duplicate queries and blank-query outcomes. Tests exercise
direct backend multi-chunk calls by lowering the chunk size; normal PDBe/Reactome
executor batch sizes do not ordinarily exceed their source chunk sizes.

Sparse optional data remains valid. The validators check fields used by projection
and permit unknown source fields; they do not implement each provider's entire schema.
An observed zero-result QuickGO response uses current=total=0. NCBI taxonomy-suggest
returns {} for no suggestions; taxonomy report absence can be explicit invalid-
identifier reports. These observed source-specific cases remain misses.

## Migration and versioning

Malformed responses previously escaping or producing false NO_MATCH/zero now yield
ERROR. Callers must distinguish unavailable/untrustworthy data from biological absence.
STRING uncorrelatable nameless edges now fail their chunk; its previous non-contract
skip test deliberately changed to assert error. All conformance/contract checks remain.
NCBI requested enrichment failure now fails the affected query instead of silently
omitting requested sequence/product/lineage data. Wikipedia retains the original query.

SPARQL HTTP 400/404 is a query/service error, not evidence of taxon absence. Wikidata
keeps the final failure reason, at most four attempts, and a 90-second elapsed chunk
budget including requests and waits. Retry-After numeric seconds and HTTP dates are
honored within that budget; excessive advice fails without an early retry. expected_rank
remains a multi-hit homonym disambiguator, not a strict rank filter.
