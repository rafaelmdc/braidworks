### Interface and migration

- STRING fan-out changes from `protein.query` names to `string.id` identifiers;
  downstream mapping uses UniProt `map_to_accession` without name re-search.
- GMrepo schema 1/2, GTDB schema 1, and MONDO schema 2 need refresh/rebuild.
  Full-resource staged builders continue preserving the old database on failure.
- BacDive rejects unsupported taxonomic granularity; existing scalar traits remain
  when observations agree. Evidence is an additional output group, not a new lookup.
- Core 0.21.4 registers only the canonical string shape for the new shared bridge,
  under its existing vocabulary exception; no biological selection logic enters core.
  STRING/UniProt/weaverkit raise their core floors to this version.
- Final versions: STRING 0.1.10, UniProt 0.2.7, GTDB 0.2.6, BacDive 0.1.10,
  MONDO 0.2.4, weaverkit 0.6.5; first-checkpoint package versions otherwise unchanged.

Provider evidence: [UniProt mapping configuration](https://rest.uniprot.org/configure/idmapping/fields)
reports STRING as a supported source/target; live taxon-scoped TP53 maps to P04637.
MONDO preserves the provider's distinction between [equivalence and SKOS exact mapping](https://mondo.monarchinitiative.org/pages/faq/)
and the [documented precision codes](https://mondo.readthedocs.io/en/latest/editors-guide/quality-control-tests/).
No new optional capabilities, database crawls, persistent cache or resume were added.
