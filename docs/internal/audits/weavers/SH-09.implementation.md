# SH-09 — group-aware work and measured performance

Group [#156](https://github.com/rafaelmdc/braidworks/issues/156), programme #147.
Implementation branch: `fix/group-aware-weaver-work`; local changes only.

## Findings and resulting behavior

| Finding | Issue | Result |
|---|---|---|
| WV-DISBIOME-002 | #263 | Schema 2 stores light columns; summaries aggregate in SQL and compact reads avoid full JSON. Full joined records remain available. |
| WV-DISBIOME-006 | #267 | Distinct species IDs share SQL/parsing within a batch; results are detached. Optional evidence filters remain proposed in #296 under #169, coordinated with #264. |
| WV-MONDO-005 | #279 | Identity is a separate always-computed group. Requested graph groups share one traversal per resolved term; the traversal provides labels, parents and shortest root depth without per-ancestor SQL. |
| WV-GTDB-007 | #238 | Crosswalk ingestion retains at most 1,000 Python rows per chunk; SQLite retains source-sized records and deterministic indexes. Tree backends retain parent links and materialize requested paths. |

| WV-FAPROTAX-006 | #261 | Parsed rules are immutable. A worker thread matches each distinct case-insensitive lineage once per batch; each result gets a separate list. |

No universal repository abstraction or cross-batch query cache was introduced.
Source-owned related issues stay open in their owning groups. Conformance and
contract tests are unchanged; new behavior regressions supplement them.

## Measurements

Harness: `tools/benchmark_weaver_work.py`, run with `--size 10000 --queries 20`.
Baseline code was the local parent commit `10912f4`; the harness was present as
an uncommitted audit tool. Measurements use temporary synthetic databases, actual
bundled FAPROTAX rules, 500 padded Disbiome experiment records, a 30-node MONDO
chain, 30 AGORA models and a balanced 2,000-leaf tree. No provider download occurs.

[Before report](../reproductions/sh09-before.json) and
[after report](../reproductions/sh09-after.json) retain timings, SQL counts,
Python allocation peaks and requested-output digests. Every corresponding digest
matches. The indexed tree case is an additional representation measurement;
forest equivalence and result detachment are tested separately.

MONDO recursive queries fall from 40 to zero for identity-only requests and to
one for graph requests. FAPROTAX matcher calls fall from 20 to one. The current
legacy all-path tree helper peaks at 1,613,290 bytes versus 1,266,850 for loading
the parent index and requesting one path. The index still scales with node count;
Newick text and the transient parsed tree also consume memory.

These are single-run characterization measurements under tracemalloc, not CI
latency thresholds or production/RSS estimates. Python allocation tracking
excludes native SQLite allocations and its sorting/temp storage. AGORA bulk
SQL slightly increases measured Python peak and wall time on this tiny fixture;
it removes model-count query growth without claiming a timing improvement.
Full-record output still needs memory proportional to the returned records.

Real-release target, before a future production memory claim: use a locally
available pinned bacterial+archaeal GTDB metadata/tree bundle, record release,
resource hashes, classification/node counts, wall time and peak process RSS for
build, tree initialization and sparse/dense query batches. Repeat the same input
and machine settings for both revisions. This group does not download a complete
release or invent a production memory budget from a synthetic fixture.

## Compatibility and migration

- Disbiome 0.3.3 requires schema 2. Rebuild schema 1 through the configured builder
  with `refresh=True` and consent/`auto_setup=True`; light columns coexist with
  unchanged full records. Input remains the species-level key established in #155.
- MONDO 0.2.5 moves ID/name/mapping fields from `term` into always-computed
  `identity`; `term` now contains parents/depth. Explicit group clients must use
  the new group for identity fields. Output-key requests are compatible; schema 3
  remains valid and no rebuild is needed for this change.
- AGORA 0.2.5, FAPROTAX 0.1.2 and GTDB 0.2.7 patch-bump their three version sites.
  Existing database formats remain valid. The lockfile and generated catalogs
  are refreshed. Public crosswalk projections retain their dict/list shape.
- Publishing #142 and persistent cache/resume #143 remain deferred.

## Verification

New regressions cover light SQL without JSON projection, per-batch work reuse,
result mutation isolation, immutable rules, worker/event-loop separation, bounded
model SQL with empty/missing coverage, streaming ingestion, shortest DAG paths,
and tree forest/node-ID equivalence including omitted and root branch lengths.
The five changed package suites pass (200 tests, six skipped); all five strict
spec/conformance/golden verification gates pass. No API fetch endpoint changed,
so no upstream live suite or bulk acquisition was required.

Workspace `make lint` and `make test` pass: 1,886 pytest tests plus five
unittest tests, 53 skipped. A final Disbiome regression caught SQLite text affinity
coercing numeric compact evidence fields. Light columns now preserve scalar types;
the updated Disbiome suite passes 30 tests (one skipped), its strict gate and
workspace lint pass again. The current aggregate is 1,887 pytest tests plus five
unittest tests. Other packages are unchanged after the full workspace run.
`git diff --check` passes. No contract/conformance tests were weakened.
